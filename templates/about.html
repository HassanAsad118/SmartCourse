About SmartCourse

Technical documentation for examiners and reviewers. This page describes the system architecture, dataset, NLP pipeline, models, and evaluation methodology.

A

Project Overview

SmartCourse is an AI-powered course recommendation system designed to help learners discover relevant online courses based on natural language queries. The system addresses the challenge of information overload in e-learning platforms, where thousands of courses make manual discovery inefficient.

Instead of relying on simple keyword search, SmartCourse applies two distinct NLP-based recommendation models — a classical TF-IDF retrieval model and a neural sentence embedding model — allowing users to compare results and understand the strengths of each approach for different query types.

B

System Architecture

Frontend

Built with HTML5, Bootstrap 5, and vanilla JavaScript (Fetch API). The interface provides a multi-page layout including a recommendation page, user dashboard, and this documentation page. All API communication is handled asynchronously without page reloads.

Backend — Flask API

Python Flask serves a RESTful API with endpoints for recommendations (/api/recommend), search history (/api/history), and saved courses (/api/save, /api/saved). The backend routes queries to the selected model and returns structured JSON responses.

ML Models

Two independent models handle recommendations. The TF-IDF model uses scikit-learn vectorization with cosine similarity for keyword-based retrieval. The Neural model uses the all-MiniLM-L6-v2 Sentence Transformer to generate dense embeddings and perform semantic similarity matching. Both models are pre-trained and stored as serialized files for fast inference.

Database — SQLite

SQLite stores user interaction data across two tables. The history table records every query with its model type and timestamp. The saved table stores courses that users explicitly bookmark, enabling the dashboard to display a personalised history and comparison view.

C

Dataset Information

The system is trained on a dataset of approximately 3,600+ cleaned courses sourced from the Udemy platform. Raw data contained 3,683 entries; after removing duplicates and rows with missing critical fields, 3,671 courses were retained for model training.

D

NLP Preprocessing Pipeline

All course descriptions pass through a standardised preprocessing pipeline before being used for model training or query matching. The same pipeline is applied to both the dataset and user queries to ensure consistency.

1
Text Cleaning

HTML tags, special characters, and punctuation are removed. Text is converted to lowercase and whitespace is normalized.

2
Stopword Removal

Common English stopwords (e.g. "the", "is", "and") are removed using spaCy's built-in stopword list to reduce noise.

3
Lemmatization

spaCy reduces each token to its base form — for example, "running" becomes "run" — improving match consistency across different word forms.

4
TF-IDF Vectorization

Preprocessed text is converted into a sparse numerical matrix using TF-IDF with unigram and bigram features (ngram_range=(1,2)), capturing both single words and two-word phrases.

5
Sentence Embeddings

The all-MiniLM-L6-v2 Sentence Transformer encodes preprocessed descriptions into 384-dimensional dense vectors, capturing semantic meaning beyond keyword overlap.

E

Model Comparison

TF-IDF Model
Keyword-Based Retrieval
  • Matches courses based on exact and near-exact keyword overlap
  • Effective for specific, well-defined queries (e.g. "Excel pivot tables")
  • Faster inference — operates on sparse vectors
  • Less effective when query and course use different vocabulary for the same concept
  • N-gram support (unigram + bigram) improves phrase-level matching
Neural Model
Semantic Embedding Retrieval
  • Understands meaning and intent behind the query
  • Matches semantically related courses even without shared keywords
  • Better for broad or conceptual queries (e.g. "I want to get into tech")
  • Slightly slower due to dense vector operations on 384-dimensional space
  • Query expansion further improves semantic coverage
F

Evaluation Metrics

Both models are evaluated using standard information retrieval metrics across a set of 10 predefined test queries with keyword-based relevance judgements. Metrics are computed at k = 10 (top 10 results).

Precision@10

The fraction of the top 10 returned courses that are relevant to the query. A score of 0.8 means 8 out of 10 results matched the expected topic.

Recall@10

The fraction of all expected relevant keywords that appear across the top 10 results. Measures how broadly the model covers the topic area.

Hit Rate@10

A binary metric per query — 1.0 if at least one relevant course appears in the top 10, otherwise 0.0. Averaged across all test queries to give an overall discovery rate.
